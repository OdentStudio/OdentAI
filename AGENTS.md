# AGENTS.md — OdentAI Segment

Инструкции для ИИ-агентов (Claude Code, Codex, Cursor и т.п.), которые работают
в этом репозитории. Подробности про поведение конвейера — в [README.md](README.md);
здесь — как работать с кодом, не сломав поставку.

## Что это

Аддон Блендера, который превращает КЛКТ (DICOM) в STL-поверхности девяти
анатомических классов. Две части, два процесса:

- **`dental9/`** — воркер на Python: чтение снимка (SimpleITK), инференс
  nnU-Net на onnxruntime (DirectML на Windows, CUDA на Linux), меши (VTK).
  Собирается PyInstaller в `dist/dental9/dental9.exe`. Точка входа — `cli.py`.
- **`addon/dental9_addon/__init__.py`** — аддон Блендера, один файл. В Python
  Блендера ничего тяжёлого нет: аддон запускает `dental9.exe` отдельным
  процессом и читает его stdout. Так падение onnxruntime или нехватка
  видеопамяти не роняют сессию пользователя.

Бренд — **OdentAI**; `dental9` — внутреннее имя, пользователь его не видит.

## Где что

| файл | что там |
|---|---|
| `dental9/cli.py` | аргументы, `--diagnose`, `--preview`, `--crop`, печать ошибок |
| `dental9/pipeline.py` | `segment()`: чтение → обрезка → ресэмплинг → инференс → второй проход по каналу → знаковые поля → STL → `report.json` |
| `dental9/infer.py` | тайлы, гауссовы веса, лестница тайлов при нехватке памяти, `SessionRef`, `readable_error` |
| `dental9/io.py` | чтение всех форм ввода, LPS/0.3 мм, нормализация CT, `crop_to_box` |
| `dental9/mesh.py` | flying edges, Taubin, децимация, перенос в координаты пациента |
| `dental9/teeth.py` | второй проход: отдельные зубы FDI, импланты, мосты |
| `dental9/preview.py` | кость порогом (Otsu) без сети — для куба обрезки |
| `dental9/sysinfo.py` | RAM, VRAM, пик памяти процесса — для логов |
| `dental9/diagnose.py` | Check system: пробный и рабочий тайл, советы |
| `dental9/winpath.py` | не-ASCII пути на Windows (8.3, копия с переименованием) |
| `addon/.../__init__.py` | панель, операторы, `_WorkerRun` (запуск воркера + лог), гизмо куба, `gpu`-оверлей |
| `scripts/pack_addon.py` | упаковка zip: код аддона + `dist/dental9` + веса |
| `scripts/export_onnx.py` | чекпоинт nnU-Net → `.onnx` + `.json` |
| `scripts/test_inputs.py` | 13 форм ввода на синтетике |

Веса (`models/*.onnx`, `*.json`, ~490 МБ) в git **не лежат**; суммы — в
`SHA256.txt`. Не коммитить `models/`, `dist/`, `build/`, `.venv/`.

## Сборка и проверка

Окружение — `.venv` (Python 3.11; сборка принимает 3.9–3.12; `onnxruntime-directml`, **не** обычный
`onnxruntime`: при обоих побеждает CPU и сборка молча теряет GPU).

```bat
:: воркер из исходников, без сборки
.venv\Scripts\python -m dental9 <скан> -o <папка> -m models\dental9.onnx [--crop ...]
.venv\Scripts\python -m dental9 --diagnose -m models\dental9.onnx
.venv\Scripts\python -m py_compile dental9\*.py addon\dental9_addon\__init__.py

:: exe (нужно, только если менялся dental9/*.py), ~1 мин
.venv\Scripts\python -m PyInstaller --noconfirm --distpath dist --workpath build dental9.spec

:: zip аддона; перед этим удалить addon\dental9_addon\__pycache__
.venv\Scripts\python scripts\pack_addon.py --model models\dental9.onnx ^
    --teeth-model models\teeth_fdi.onnx --out dist\OdentAI.zip
```

`build_windows.bat` делает всё сразу, но в конце ждёт `pause` — для агента
удобнее шаги выше.

Аддон проверяется в самом Блендере:

- `blender -b --factory-startup --python test.py` — регистрация, `_load` операторов,
  синхронный запуск воркера. **Модальные операторы в `-b` не работают**
  (нет цикла событий).
- `blender --factory-startup --python test.py` (с окном) — настоящие
  модальные операторы, гизмо, скриншоты через `bpy.app.timers` +
  `bpy.ops.screen.screenshot`, выход через `bpy.ops.wm.quit_blender()`.
- В тесте можно подменить `A._exe` и `A._prefs` у модуля, чтобы гонять аддон
  из исходников против `dist/dental9/dental9.exe` и `models/`.

## Правила

**Язык.** Всё, что видит пользователь (UI, лог, ошибки, подсказки), —
английский: аддон уезжает в клиники. Комментарии и docstring — английские,
по стилю окружающего кода: объясняют **почему** и часто с датой и случаем, на
котором это ломалось. README — английский; AGENTS.md и `ЧТО_ЗАПУСКАТЬ.txt` — русские.

**Не ломать предобработку.** LPS, шаг 0.3 мм, нормализация из отпечатка
обучающего набора (не по снимку), тайл кратен делителю сети (32, 64, 64) и не
меньше двух делителей. Параметры живут в `dental9.json` рядом с весами и
меняются только вместе с ними. Ошибка здесь не падает, а даёт правдоподобный
неверный результат.

**Не глотать ошибки.** Лестница тайлов ловит только нехватку памяти и потерю
устройства (`infer.is_oom`, `is_device_lost`). Любой другой сбой — наружу.
Тихий результат похуже, который выглядит нормально, — худший исход.

**Диагностика — не повод упасть.** Всё в `sysinfo.py` best effort: нет ответа —
`None`, не исключение.

**Аддон и воркер общаются только через командную строку и stdout.** Строка
`ERROR: …` в выводе — то, что увидит пользователь; подробности после неё —
для лога. `report.json` в выходной папке — машинный итог прогона.

**Пути на Windows.** Всё, что уходит в ITK/GDCM/VTK, — через
`winpath.readable`/`writable`: нативные библиотеки не открывают не-ASCII пути.

**Blender API.**
- Минимальная версия в `bl_info` — 3.0, боевая — 5.2. Где API менялось
  (`stl_import`, auto smooth, `surface_render_method`), поддерживаются обе ветки.
- В `draw`/`poll`/draw-хендлерах ничего не писать в ID-данные — Блендер это
  запрещает.
- Куб обрезки: объект из 8 вершин без рёбер, рисует его оверлей, двигают гизмо
  (`DENTAL9_GGT_crop_box`). Намеренно **не** дочерний к превью.
- Хендлеры гизмо каждый раз ищут куб заново через `scene.dental9.crop_box`:
  группа живёт дольше любого куба.

**Удаление файлов.** Папку сборки синхронизируют между Linux и Windows; то,
что выглядит мусором (`.venv`, `build`, `dist`), может быть чужой готовой
сборкой. Не удалять ничего без прямой просьбы пользователя.

## Выпуск версии

1. Поднять `bl_info["version"]` и `VERSION_LABEL` в `addon/.../__init__.py`.
2. Пересобрать exe (если менялся воркер) и zip, проверить в Блендере.
3. Коммит; сообщение по-английски: что и почему. Установленную копию аддона
   в Блендере правкой не считать — источник правды здесь.
